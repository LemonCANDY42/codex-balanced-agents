This is a descriptive snapshot of the author's locally recorded Codex activity on **2026-09-05, 00:00–19:05:16 (Asia/Singapore, UTC+08:00)**. It is a partial day, not a benchmark or an evaluation of the released Balanced preset. No private session content is published here.

这是一份作者本机 Codex 的个人使用记录，时间为 **2026-09-05 00:00–19:05:16（Asia/Singapore，UTC+08:00）**，并非完整一天，也不是基准测试或已发布 Balanced 预设的效果评估。这里仅公开汇总数据。

## Coverage and counting / 覆盖范围与口径

The scan found **15 unique active root sessions**: 13 user sessions, one automation and one other/unclassified session. **3 of 13 user sessions (23.1%)** had active children; that is **3 of 15 roots (20.0%)** across all root types. The three user roots contributed 49, 9 and 8 children respectively, so this is a concentrated sample rather than 66 independent top-level tasks.

去重后有 **15 个活跃主会话**：13 个用户会话、1 个自动化会话和 1 个其他／未分类会话。其中 **3/13 个用户会话（23.1%）** 有活跃子代理；若包含全部主会话类型，则为 **3/15（20.0%）**。三个用户主会话分别贡献 49、9、8 个子会话，样本较集中，不能看成 66 个独立的顶层任务。

Activity was checked against timestamped local session records within the fixed window, including sessions created before that day. Database metadata supplied candidate paths and parent–child relationships, but modification times alone were not treated as activity. Multiple files for the same session ID were deduplicated. The statistics agent and its descendants were excluded; unrelated earlier activity in its parent session remained eligible.

统计使用固定时间范围内的本地会话时间戳确认活动，包含此前创建、当天仍活跃的会话。数据库元数据用于定位候选记录和父子关系，没有仅凭修改时间判定活跃；同一会话 ID 对应多个文件时去重。负责统计的子代理及其后代被排除，其父会话此前的其他活动仍可纳入。

All 66 included children had a recorded parent–child edge and an in-window `turn_context.payload.model` matching the database model, with no model-attribution gaps in this included sample. This confirms recorded child-session creation and model attribution, not successful task completion or provider-level inference. Direct successful `spawn_agent` tool calls were not independently counted, so the tables use **child sessions**, not raw API/tool calls.

66 个纳入统计的子会话均有父子关系记录，且时间范围内的 `turn_context.payload.model` 与数据库模型一致；纳入样本内没有模型归属缺失。这证明了子会话创建和记录中的模型归属，不代表任务完成或服务端推理成功。未独立统计成功的 `spawn_agent` 工具调用，因此下表按**子会话**计数，而非原始 API／工具调用次数。

## What this can tell us / 如何理解

The Astra share is an observed model-selection share, not a difficult-task rate. Review alone accounts for 27 of the 66 children; UI roles in that snapshot also followed a model preference that does not label task difficulty. The records have no independently validated difficulty labels. They cannot establish success rates, quality, cost savings or how often escalation was necessary.

Astra 占比表示实际选用模型的分布，不能称为困难任务占比。仅审查角色就占 66 个子会话中的 27 个；当时的 UI 角色也有特定模型偏好，不等于任务难度标签。记录没有经过独立验证的难度标注，无法据此证明成功率、质量、成本收益或升级是否必要。

The sample describes one person's workload and local configuration, which changed over time. In particular, it does not compare Quality against Balanced or prove that the released package caused this distribution. Session counts are not token-, time-, cost- or task-weighted, and local records do not cover unrecorded activity on other devices or cloud services.

样本反映的是一个人的工作内容与随时间变化的本地配置，并未对比 Quality 与 Balanced，也不能证明调用分布由公开项目带来。子会话数量没有按 token、耗时、成本或任务加权，本机记录也不覆盖其他设备或云端未保存在本地的活动。

This snapshot is one reference for [future role-tier and model-selection updates](design.md#how-the-tiers-will-evolve--后续优化与分级), alongside task completion, rework, latency and hands-on experience. The package does not collect telemetry or change installed models automatically.

这份记录仅作为[后续角色分级与模型选择调整](design.md#how-the-tiers-will-evolve--后续优化与分级)的参考之一，还需结合任务完成情况、返工、耗时和使用体验。本项目不会收集遥测或自动修改已安装模型。
